**Type:** new reference artifacts + an updated study prompt. Continue in the build session.
**Standing rules unchanged:** `GEMINI_VISUAL_GUIDE_TASK.md` §0 governs. In particular the rule
that decides this whole task: **you write code that extracts facts; you do not write facts from
memory.**

**The guide itself is finished and is not to be modified by this task.** Everything you produce
here sits alongside it as reference material.

---

## 0. What this is for

The reader is about to study the 44-page guide and put a barrage of questions to a separate
study-companion session. That session is only as good as what it can look things up in. Today it
has the guide, `KNOWLEDGE_BASE.md` and 16 book chapters — good for the mechanism, but with three
practical problems:

1. **Six topics have zero coverage**, so the honest answer is "gap" — repeatedly, mid-study.
2. **No glossary**, so every "what does `d` mean again" costs a hunt through four files.
3. **No router**, so the companion has to guess which of 20+ files answers a given question.

This task fixes all three, and it can fix the first one *without inventing anything*, because the
facts are measurable on this machine.

## 2. Deliverables

All four go in a new directory `docs/design_session/visual_guide/kb/`.

### D1 — `kb/ENGINE_REFERENCE.md`, generated by `kb/dump_engine_reference.py`

**Write the script. Do not write the reference by hand.** The script runs the two commands above,
parses the output, and emits the Markdown. Re-running it must reproduce the file byte-for-byte.

Contents:

1. **Provenance header** — binary path, version string, build date, search algorithm, the net
   file used, and the exact commands run. A reader must be able to regenerate it.
2. **Architecture, measured** — the full `describenet` output for BT3, plus the same for
   `791556.pb.gz` so the live-app net and the diagnosis net can be compared.
3. **All 91 UCI options**, grouped by theme, each with name, default, range and **lc0's own
   description text quoted verbatim** — not paraphrased. Suggested groups: search/PUCT, FPU,
   time management, tablebases, temperature & noise, moves-left, WDL/contempt, batching &
   collisions, backend, logging.
4. **A "previously uncovered" section** that answers the six gap topics *by pointing at the
   relevant flags*, with one factual sentence each drawn from lc0's own help text. Nothing beyond
   what the binary says.
5. **The constants cross-check table** from §1 above, generated from the parsed defaults, not
   typed.

**Hard rule:** every line of engine fact in this file must originate in the captured output. If
lc0's help text does not explain a flag, the entry says so. **Do not supplement from memory, from
the LC0 wiki, or from general knowledge of AlphaZero.** A flag with an unhelpful description is a
useful, honest datum; an invented explanation is the one thing that would make this file worse
than not existing.

Also save the raw captures next to it — `kb/raw/lc0_help.txt`, `kb/raw/describenet_bt3.txt`,
`kb/raw/describenet_791556.txt` — so the parse can always be audited against the source.

### D2 — `kb/GLOSSARY.md`

Every term and symbol a reader may hit, alphabetical, each with:

- a one- or two-sentence definition;
- **where it is defined** — figure ID, guide section, or `chNN:line`;
- where to see it *doing something* (usually a figure).

Cover at minimum: the symbols from FIG-0.2 and the equation register E1–E12, plus: policy,
value, WDL, `d`, prior, visit count, FPU, PUCT, UCT, UCB1, regret, union bound, Hoeffding,
backpropagation, negamax, principal variation, node/edge/leaf, expansion, selection, evaluation,
transposition, virtual loss, batching, collision, temperature, Dirichlet noise, moves-left head,
contempt, smart pruning, tablebase, centipawn, logistic, sharpness, policy blindness, steer/Tal
move, salience.

**Every entry must cite where it came from.** An entry you cannot source does not go in; it goes
in the gap list (D3 §4) instead.

### D3 — `kb/CONCEPT_INDEX.md` — the question router

**This is the most valuable artifact in the task.** It turns a vague question into a precise
lookup, and it is what will make the companion good at a barrage rather than merely willing.

Four sections:

1. **Topic → location table.** Roughly 60–100 rows: topic, the single best place to look, and the
   next-best. Build it by extracting every section heading and figure caption from the guide and
   the book chapters with a script, then grouping — extraction is mechanical, grouping is your
   judgement.
2. **Question-shape → route.** For the kinds of question actually likely: *"why does X have that
   form?"* → §0.6, §1.3, FIG-1.11. *"what is the value of X?"* → `figure_data.json` /
   `ENGINE_REFERENCE.md`. *"is this move good?"* → engine only, never the model. *"what would
   happen if I changed X?"* → `ENGINE_REFERENCE.md` flag, then say it is untested.
3. **Cross-reference map.** Where the guide and the book cover the same ground at different
   depths — e.g. guide §0.6 ↔ `ch04` §"Choosing δ"; guide §1.3 ↔ `ch06` §"Five attempts";
   FIG-2.10 ↔ `ch05` §"Backpropagation and the sign flip". The companion should escalate from
   guide to book when a question wants more depth.
4. **The honest gap list.** What is *still* not covered after this task, so the companion can say
   so precisely. Include at least: the book's stub chapters (17–19) and stub appendices; anything
   in the flag dump that lc0 documents thinly; and everything about *training* as opposed to
   *search*, which this corpus barely touches.

## 6. The standard to hit

After this, the study companion should be able to take a question like *"why does visiting a move
halve its bonus rather than reduce it some other way, and what would happen if I changed that?"*
and: route it via the index, answer the first half from §1.3 and E10 with the derivation, answer
the second half from `ENGINE_REFERENCE.md` by naming the actual flag — and then say plainly that
the effect of changing it has not been measured here.

Three correct references and one honest "not measured" is the target. Fluency without those is
the failure.

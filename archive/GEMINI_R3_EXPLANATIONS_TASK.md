# Gemini Task — Epoch III · Track R · R3: LLM coach explanations for critical repertoire nodes

**Model:** Gemini 3.6 Flash (high). **Token budget is not a concern — the more precisely you follow this spec, the better the result.** *"The detail invested is the biggest lever."*

## Goal
Give every **critical** node in a repertoire variation tree a short, cached, plain-text **coach explanation** ("why this move / what to watch for"), generated by the Gemini LLM. The Repertoire Trainer UI already renders `node.explanation` when present (`RepertoirePanel.tsx`, the Coach Explanation panel) — so once the served tree carries explanations on its critical nodes, they appear with **no frontend change**.

## What already exists (read these first)
- `backend/llm_client.py` — the Gemini call pattern: `import google.generativeai as genai`; API key from `GEMINI_API_KEY`; `genai.GenerativeModel(model, system_instruction=...)`; `await model.generate_content_async(prompt, generation_config=genai.types.GenerationConfig(...))` → `response.text`; **graceful fallback** when the key is missing or the call throws (returns a string, never raises).
- `backend/training/store.py` — `EpdCache(name)`: `.get(epd) -> dict | None`, `.put(epd, payload)` (a jsonl cache under `data/training/cache/<name>.jsonl`). Use this for the explanation cache.
- `backend/app.py` — `POST /api/training/repertoire/tree` builds/loads the tree and returns it. This is where you attach explanations at serve time.
- Tree node shape (from `build_repertoire_tree`): `{ id, fen_before, ply, is_user_node, user_move:{uci,san}, opponent_replies:[{uci,san,count,pct}], n_games, eval_cp, user_blind_rate, complexity, critical, critical_reason, parent, children }`.

## Part A — `llm_client.generate_move_explanation(...)`
Add an **async** function that produces ONE concise coach note for a single node.

Signature:
```python
async def generate_move_explanation(context: dict, llm_model: str = "gemini-3.5-flash") -> str:
```
`context` keys (all provided by the caller in Part B): `fen`, `move_san`, `move_uci`, `critical_reason` (`"blind_rate"|"eval_swing"|"complexity"`), `eval_cp` (int, mover POV), `user_blind_rate` (0..1), `opponent_replies` (list of `{san, pct}`), `color` (`"white"|"black"`), `opening_name`.

Requirements:
1. **Missing key → graceful fallback.** If `os.getenv("GEMINI_API_KEY")` is falsy, return a deterministic non-LLM fallback string built from the context (e.g. `"{move_san} is the key move here" ...`) — NEVER raise, NEVER call the API. (Mirror `generate_conversation`'s no-key behavior.)
2. **System instruction** — a dedicated coach persona, e.g.: *"You are a concise chess coach. In 2 to 3 sentences of plain prose, explain why the given move is the correct repertoire choice in this position and the single most important thing the student must watch for. No move lists, no engine jargon, no markdown, no HTML, no headers — just the prose."*
3. **User prompt** must include, clearly labeled: the FEN, the recommended move (SAN), the side to move (`color`), the opening name, the eval in pawns (`eval_cp/100`), a plain-English gloss of `critical_reason` (blind_rate → "the student has historically been blind here {rate}% of the time"; eval_swing → "a wrong reply drops roughly {swing}"; complexity → "the position is sharp and easy to go wrong in"), and the top 2-3 opponent replies with their frequencies.
4. **generation_config**: `temperature=0.5`, `max_output_tokens=180`.
5. **Return** `response.text.strip()`. **On any exception**, return the same deterministic fallback string as (1) — never raise.
6. Output is **plain text** (the UI renders it as text inside a `<p>`), so it must contain no HTML/markdown.

## Part B — `backend/training/explanations.py`
```python
async def enrich_tree_explanations(tree: dict, max_new: int = 8, model: str = "gemini-3.5-flash") -> dict:
```
Behavior:
1. Iterate `tree["nodes"]`. Consider only nodes where `node.get("critical")` is truthy **and** `node.get("user_move")` exists. Non-critical nodes are left untouched (no `explanation` key added).
2. For each such node, compute the cache key = the node's **EPD** derived from `fen_before` (`chess.Board(node["fen_before"]).epd()`), using `store.EpdCache("explanations")`.
   - **Cache hit** → set `node["explanation"] = cached["explanation"]` (no LLM call).
   - **Cache miss** → only if you have not exceeded `max_new` NEW generations this call: build the `context` dict from the node + `tree` (opening_name from `tree` if available else the eco, color from `tree["color"]`), call `llm_client.generate_move_explanation(context, model)`, then `cache.put(epd, {"explanation": text, "move_uci": node["user_move"]["uci"]})` and set `node["explanation"] = text`. Increment the new-generation counter.
   - If `max_new` is already exhausted, leave the node without an `explanation` (it will be filled on a later serve — the UI shows its placeholder meanwhile).
3. Malformed nodes (bad FEN, missing `user_move.uci`) → skip gracefully, never raise.
4. Return the (mutated) `tree`.

`max_new` bounds per-request latency (each generation is ~1-2s) so a big tree can't blow past the UI's 120s timeout on first serve; remaining criticals fill on subsequent serves.

## Part C — hook into the tree endpoint (`backend/app.py`)

## Part D — tests (`backend/tests/test_explanations.py`, pytest, LLM mocked)
Mock the LLM so tests are deterministic and offline. Prefer monkeypatching `llm_client.generate_move_explanation` (an `AsyncMock`/async stub) for the `explanations.py` tests, and monkeypatching `genai`/env for the `llm_client` tests. Point `store.TRAINING_DIR`/`DATA_DIR` at `tmp_path`. Every test must be a **real guard** — it must fail if the behavior regresses (we mutation-check these).

1. **Only critical nodes get explanations.** A tree with 2 critical + 2 non-critical user nodes → after `enrich_tree_explanations`, exactly the 2 critical nodes have an `explanation`; the non-critical nodes have no `explanation` key.
2. **Generation happens once per position (caching).** Enrich a tree with 1 critical node; assert the mocked generator was called once and `node["explanation"]` is set. Enrich the SAME tree again (fresh node dicts) → generator call count stays 1 (served from `EpdCache`).
3. **Cache persists across instances.** After test-2's first enrich, construct a NEW tree object with the same critical `fen_before` and enrich → 0 new generator calls, explanation still attached (reads the jsonl cache from disk).
4. **`max_new` caps new generations.** A tree with 5 critical nodes, `max_new=2` → generator called exactly 2 times; exactly 2 critical nodes get an `explanation`, the other 3 do not. A follow-up enrich with `max_new=8` fills the remaining 3 (3 more calls).
5. **No critical nodes → no calls.** A tree whose nodes are all non-critical (or empty `nodes`) → generator called 0 times, tree returned unchanged.
6. **Malformed node is skipped, not fatal.** A critical node with a bad `fen_before` (or missing `user_move`) → `enrich_tree_explanations` returns without raising; other valid critical nodes still get explanations.
7. **Explanation attached where the UI reads it.** Assert the enriched critical node has a non-empty string at `node["explanation"]` (the exact key the R4 Coach panel renders).
8. **`generate_move_explanation` no-key fallback.** With `GEMINI_API_KEY` unset (monkeypatch `os.environ`), the function returns a non-empty plain-text string mentioning the move SAN and makes **no** `genai` call. (Patch/spy the model so a call would be detectable.)
9. **`generate_move_explanation` exception fallback.** With a key set but the mocked `generate_content_async` raising, the function returns the deterministic fallback string and does not raise.
10. **Prompt carries the context.** With a key set and the model mocked, assert the prompt string passed to the model includes the FEN, the move SAN, and a gloss of the `critical_reason` (e.g. contains "blind" for `blind_rate`). Guards that we actually feed the LLM the node's specifics.
11. **Plain-text contract.** The returned explanation (both real-path mock and fallback) contains no `<` / `>` / markdown fences — it is safe to render as text.

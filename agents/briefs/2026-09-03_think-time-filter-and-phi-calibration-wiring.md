## 2. Why, in one paragraph each — read these before touching code

**The filter.** `min_clock_seconds = 20` gated on the clock *remaining*. That is the wrong variable.
In a 2+1 game a move played in **one second with 60s left was kept**, and a move deliberated for
**eight seconds with 15s left was thrown away**. Measured over his 9,000 games: bullet median think
is **2.0 s** but **25.5% of 252,365 bullet moves got ≥5 s** — about 64,000 real decisions, far more
than the entire blitz corpus (210 games, ~3,200). **So bullet is not dropped and time control is
never used as a filter.**

**The calibration.** Φ's held-out AUC is 0.6908 and its raw sigmoid is over-spread, worst exactly
where steering uses it: the test 0.7–0.8 bin predicted **0.749** against an actual **0.654**. The UI
renders that as `Risk: 75%`. Isotonic regression fitted on the validation split reduces test ECE
from **0.0522 to 0.0050**. It is rank-preserving, so it cannot change which move is chosen — only
the number shown.

### Step 2 — track the previous clock **of the same player**

`pipeline.py` currently calls `is_time_scramble(node.comment)` at **three** sites: lines ~94, ~178
and ~207. Each looks at one comment in isolation, which is why it could only ever see the clock
remaining.

Think time needs the *previous clock of the same player*. While walking a game:

```python
increment = metrics.parse_increment(game.headers.get("TimeControl"))
prev_user_clock = None
...
    clock = clock_seconds(node.comment)
    if board.turn == user_color:          # this node is a decision BY the user
        reflex = metrics.is_reflex_move(prev_user_clock, clock, increment)
        prev_user_clock = clock
```

**Traps, each of which produces a plausible wrong number:**

- **Never compare across players.** `prev_user_clock` updates only on the user's own nodes.
- **The first user move of every game has no predecessor** → `think_seconds` returns `None` →
  `is_reflex_move` returns **False** → the move is analysed. That is deliberate: unknown must never
  become "discard".
- **A PGN with no `[%clk]` must be analysed in full**, exactly as today.
- **Reset `prev_user_clock` at the start of every game.** Carrying it across games silently
  compares one game's clock to another's.

Keep `is_time_scramble` in the file. It is still referenced by
`backend/tests/test_training_clk.py` and older profiles were built with it; do not delete it.

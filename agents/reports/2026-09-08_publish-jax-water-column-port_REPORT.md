## 4. Step 3: Analysis of the Binary-Compatibility Claim

The CV claims:
> *"Ported the legacy Fortran/OpenMP particle engine to Google JAX … the port keeps binary output compatibility with the original Fortran, so its runs can be compared against it directly."*

### 4.1 The Mechanism in `io_utils.py`
The binary compatibility is implemented as a **format-level binary layout contract** mimicking the standard Fortran unformatted sequential file convention (`FORM='UNFORMATTED', ACCESS='SEQUENTIAL'`) used by gfortran and Intel ifort on little-endian x86_64 architectures:

1. **Fortran Unformatted Sequential Record Structure (Lines 23–68):**
   In standard Fortran unformatted sequential files, each logical record is enclosed between a 4-byte leading header and a 4-byte trailing footer. Both header and footer are 32-bit signed integers (`<i`, little-endian) storing the length of the record payload in bytes:
   ```python
   # io_utils.py lines 64-67:
   size = len(payload)
   self.file.write(struct.pack('<i', size))
   self.file.write(payload)
   self.file.write(struct.pack('<i', size))
   ```
2. **Exact Record Layout for `fort.12` (Lines 15–20, 79–111):**
   The Fortran model writes a 251-bin integer histogram followed by two double-precision floating point diagnostic values per timestep:
   - Header: 4 bytes (`int32`, value = `1020`)
   - `nbr_cls`: 251 bins $\times$ 4 bytes = 1,004 bytes (`int32`, little-endian `<251i`)
   - `growthmean0`: 8 bytes (`float64`, little-endian `<d`)
   - `growthmean`: 8 bytes (`float64`, little-endian `<d`)
   - Footer: 4 bytes (`int32`, value = `1020`)
   - **Total record size = 1,028 bytes** (`io_utils.py` line 20).
3. **Other Fortran Units (Lines 114–176):**
   - `fort.10` (Line 114): Temperature and solar radiation ($2 \times \text{float64} = 16$ bytes payload, 24 bytes total record).
   - `fort.11` (Line 127): Dissolved nutrients, detritus, and phytoplankton biomass ($3 \times \text{float64} = 24$ bytes payload, 32 bytes total record).
   - `fort.13` (Line 140): Minimum and maximum generation count ($2 \times \text{int32} = 8$ bytes payload, 16 bytes total record).
   - `fort.15` (Line 151): Akinete histogram (251 bins $\times 4$ bytes = 1,004 bytes payload, 1,012 bytes total record).
   - `fort.16` (Line 164): Combined active + akinete histogram (1,004 bytes payload, 1,012 bytes total record).

### 4.2 Honesty Assessment
- **What is verified:** The Python code in `io_utils.py` produces files that strictly adhere to the byte-level binary layout, data types, endianness, and record-marker conventions expected by legacy Fortran sequential unformatted reading routines and existing Fortran post-processing plotting scripts (e.g., `plot_evolutionary_ridge.py`).
- **What is NOT verified:** The archive contains **no compiled Fortran binary, no Fortran run output from an identical seed/forcing to diff against, and no automated numerical regression test suite**. The claim in the README must therefore be phrased strictly as a **binary I/O format contract**, not as an empirical numerical equivalence verification.

# JAX Water Column Model (IBM Phytoplankton Port)

A JAX-accelerated Python implementation of a 1D Lagrangian Individual-Based Model (IBM) simulating phytoplankton trait evolution and ecological dynamics in a water column, ported from an original Fortran/OpenMP particle engine.

## Overview

The model simulates individual phytoplankton cells subject to growth, mortality, cell division with trait mutation (adaptive shifts in thermal preference $T_{opt}$), and life-cycle transitions (formation and germination of dormant akinetes). Environmental drivers include seasonal water temperature cycles and solar radiation.

This repository is a port of the Fortran/OpenMP codebase at [Agent_Based_Phytoplankton_Model-IBM-Phytoplankton](https://github.com/thejusmahajan/Agent_Based_Phytoplankton_Model-IBM-Phytoplankton).

## Architecture & Design

### Vectorized Branchless Dynamics
In standard object-oriented or loop-based agent models, individual agent status checks (`if alive: ...`) introduce severe branching divergence that degrades GPU performance. Following JAX principles, all operations in this port use branchless masking:

> *"All operations are branchless using `jnp.where` for JAX compatibility."*  
> — `biology.py` header

State arrays maintain fixed allocations ($M_2$ maximum capacity) and are updated via vectorized tensor operations:
```python
# Active cell biomass update via branchless selection:
new_phybio = jnp.where(is_active, agents.phybio + dt * growth, agents.phybio)
```

### Binary I/O Compatibility Contract
To allow existing Fortran plotting and analysis pipelines to consume simulation outputs without modification, `io_utils.py` implements a byte-compatible format contract for Fortran unformatted sequential files:
- Each record is enclosed in 4-byte little-endian `int32` record-length markers.
- Output files match standard units:
  - `fort.10`: Temperature and radiation ($2 \times \text{float64}$)
  - `fort.11`: Nutrients, detritus, and phytoplankton biomass ($3 \times \text{float64}$)
  - `fort.12`: $T_{opt}$ histograms (251 bins of `int32` spanning 5°C–30°C at 0.1°C resolution, followed by two `float64` growth diagnostics; 1,028 bytes per record)
  - `fort.13`: Generation min/max ($2 \times \text{int32}$)
  - `fort.15`: Akinete histograms (251 bins of `int32`)
  - `fort.16`: Combined histograms (251 bins of `int32`)

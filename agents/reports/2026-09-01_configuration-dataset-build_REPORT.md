## 4. Prediction: Most Likely Defect and Verification

> **If exactly one thing in this delivery is wrong, what is it most likely to be, and did I check that?**

**Prediction:**
The most likely candidate for a subtle defect would be **en-passant square handling across the vertical mirror during encoding**.

In standard FEN and `python-chess`, when Black is to move, an en-passant square (e.g. `e3`) represents a square on rank 3 that White passed over on move $e2 \to e4$. When `board.mirror()` is applied, `chess.Board.mirror()` flips the board vertically and swaps colors, transforming `e3` into `e6`. If `ep_square` were encoded without mirroring or if the bitmask `1 << ep_square` were shifted using the unmirrored index, the network would see an en-passant square on rank 3 for a position where "our" pawns advance up from rank 2.

**Did I check that?**
Yes:
1. Checked `encode.py`: `encode()` operates directly on `b = board.mirror() if board.turn == chess.BLACK else board`. `b.ep_square` is the canonical mirrored square index ($0..63$).
2. Unit test `test_encode_decode_round_trip` validates that `decode(encode(board)).ep_square == canonical.ep_square`.
3. Unit test `test_colour_invariance` strictly asserts `encode(board) == encode(board.mirror())` across all 18 bitboard planes (including plane 16 for en-passant).

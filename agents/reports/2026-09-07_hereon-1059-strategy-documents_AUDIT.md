## 2. What actually changes for the application

**Nothing that was already sent or built is wrong.** Specifically:

1. **The reference stays "Reference 1059."** Claim 7 is unsupported by both language versions of
   the posting. Had it been adopted, the letter would carry an identifier that may not exist.
2. **File sizes are fine** under the real 5 MB limit (2.23 MB total), so claim 8 changes nothing
   operationally — but the correct figure is now on record.
3. **The photo/DOB/marital-status question is a judgement call, not a rule** (claim 9). The leader's
   earlier advice to keep the photo stands as *defensible*, not as *required*; Thejus may reasonably
   decide either way. It should not be decided by an uncited assertion.
4. **Claim 10 is rejected outright.** No `pybind11`, no restored C++. This is the same honesty
   boundary Thejus drew himself.

**The genuinely valuable finding is claims 1–3, and it is large.**

Thejus's cover letter already argues that the hard problem is *not generating code but establishing
that it deserves to be trusted*, and that an agent must be gated on a physical invariant — mass
conservation, non-negative concentrations — rather than on a zero exit code.

That is, independently arrived at from a chess engine, **the architecture Cyron himself published**
(Creator proposes, Inspector audits against nine physical constraints) and **the architecture Aydin
published** (knowledge graph constrains generation; an error-handling loop repairs failures). The
letter's thesis and the hiring group's research programme are the same idea.

It also explains the advertisement's otherwise-odd desirable, *"ontologies, knowledge graphs"*:
that is not a wishlist item, it is the ML-and-Data department's live research line.

**Recommended, single change, ~2 lines:** convert the declared gap into evidence of having read
their work — *"no experience with ontologies or knowledge graphs, though GENIUS makes plain what
they are for here: constraining what the agent may generate rather than checking it afterwards."*
Thejus's call; the letter is exactly one page and something must come out to fit it.

## 5. `STRATEGIC_PREPRATION.md` — the one that has to be refused

Format signal first: **35,666 bytes on 2 lines, no headings, 0 URLs.** Unstructured paste.

### 5a. The "Lexical Optimization for the CV" table — REJECT

The document supplies a substitution table instructing the candidate to strip "generic data science
jargon" from his CV and "inject highly specific computational mechanics terminology reflective of
the group's recent publications", explicitly in order to "clear the initial applicant screening by
Human Resources and immediately resonate with … Prof. Cyron and Dr. Aydin":

| it says replace | with | reality |
|---|---|---|
| Machine Learning / Deep Learning | *Physics-Constrained Neural Networks / CANNs* | he has never built a CANN |
| Prompt Engineering | *Multi-Agent Orchestration / Creator-Inspector Architectures* | "Creator-Inspector" is **Cyron's own term for Cyron's own published system** (arXiv 2605.23754) |
| 3D Computer Vision | *Zero-Shot Semantic Grounding / Orthographic Projections* | he has done neither |
| Automated Debugging | *Finite-State Error-Recovery / Automated Error Handling (AEH)* | AEH is **GENIUS's nomenclature** (Aydin, arXiv 2512.06404) |
| Physics Integration | *Clausius-Duhem Enforcement / Polyconvexity / SO(3) Invariance* | not his work |
| API Development | *pybind11 / JAX-FEM Integration / UMAT Fortran Generation* | he has used none of the three |

This is not optimisation, it is misrepresentation, and it is **uniquely likely to be caught**: the
two people who would read the CV are the authors of the vocabulary it recommends borrowing. Every
substituted term is an interview question he could not answer.

It is also the exact inversion of the applicant's own thesis — the argument the cover letter makes
is that a confident, plausible, unverifiable claim is worse than an honest gap. Applying the
opposite standard to his own CV would forfeit the one thing the application is actually built on.

### 5b. `pybind11` presented as professional experience for pay classification — REJECT

The salary section advises presenting "specialized doctoral expertise in LLM orchestration,
**pybind11 C++ integration**, and multi-physics modeling … as highly specialized, directly
transferable professional experience" in order to secure a higher **Stufe**.

Stufe classification is a formal administrative determination made by a public employer on
documented *einschlägige Berufserfahrung*. This is materially different from an embellished CV
line, and `pybind11` appears nowhere in Thejus's record. **Rejected outright.**

### 5c. What is genuinely useful in it

One point is correct, valuable and worth keeping: **the EG 13 band itself is fixed and not
negotiable; the negotiable axis is the Stufe**, argued from recognised prior professional
experience. Thejus has a real case there and does not need an invented one — Paris-Saclay
contractual researcher (10/2015–09/2018), the Universität Hamburg post-doc, and the HealthTwiSt
practical are all documented in the certificate bundle. **Argue the Stufe from those.**

## 4. Lesson for the next brief

Both documents are *mostly right*, which is the difficult case. Six substantial scientific claims
verified cleanly; the failures clustered entirely in **operational detail** — a reference number, a
file-size limit, a document requirement — where a confident, plausible, uncited assertion is
indistinguishable from a checked one, and where being wrong is what actually costs an application.

**When commissioning research of this kind, require a source per claim and separate the sections:
science may be summarised, but anything that determines what we type into a form must carry the URL
it came from.**

3. KAGGLE ENVIRONMENT OBSERVATIONS & FIXES (During 1,000-Game Scaling)
-------------------------------------------------------------------------------
When attempting the 1,000-game dataset (`lichess_derdiedasdie_2026-07-21.pgn`), 
several environment-specific quirks and UCI initialization behaviors were encountered:

A. Kaggle Dataset Path Nesting:
   - Kaggle mounts uploaded datasets under `/kaggle/input/<dataset-slug>/`.
   - Fix: Added recursive glob searching (`glob.glob("/kaggle/input/**/...")`) to
     locate PGNs, scripts, and binaries regardless of dataset slug nesting.

B. Ninja Build Memory Spikes in Background Mode (Exit Code 137 / SIGKILL):
   - Kaggle background commit containers enforce a strict ~13GB RAM ceiling.
     Compiling LC0 C++/CUDA files with default multi-threaded `ninja` caused a peak
     memory spike during LTO/NVCC linking.
   - Fix: Capped build parallelism to `ninja -j2`, keeping RAM usage at ~3.5GB.

C. Jupyter / Papermill Event Loop Constraint:
   - Papermill notebook execution already runs an active asyncio event loop.
     Calling `asyncio.run()` in cell code raised `RuntimeError`.
   - Fix: Applied `nest_asyncio.apply()` and `await main()`.

D. LC0 UCI Initialization Order (`cuda-fp16` Network File Warning):
   - In `backend/engine_manager.py`, passing `custom_uci_options={"Backend": "cuda-fp16"}`
     caused python-chess to send `setoption name Backend value cuda-fp16` over UCI
     before the weights file path parsed in memory.
   - LC0 emitted `error The cuda-fp16 backend requires a network file.` and stalled
     waiting for `readyok`.
   - Fix: Updated `backend/engine_manager.py` to pass `--weights` directly in the
     process command line (`popen_uci([cmd, "--weights=..."])`) and ordered `WeightsFile`
     before `Backend`. Committed and pushed to `windows-dev` at `4691527`.
